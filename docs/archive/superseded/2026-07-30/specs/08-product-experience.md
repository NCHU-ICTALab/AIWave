# 08・會員產品體驗與 AI 互動

> 狀態：現行體驗基線  
> 更新日期：2026-07-28  
> 前一版本已封存至 [archive](../archive/superseded/2026-07-28/specs/08-product-experience.md)。

## 1. 體驗原則

1. 首頁先回答「我現在有什麼、該處理什麼」，完整 AI 在獨立頁面承接複雜任務。
2. AI 是整個系統的自然語言操作層，不是藏在側欄的 FAQ。
3. 每個服務、推薦與訂單卡片都必須有下一步，不放只能看的條列。
4. 每個數字可追溯到官方資料、seed、規則或明確標示的情境。
5. 群組能力以會員同意、角色、active scope 與可撤回為前提。
6. WCAG 2.2 AA、鍵盤、螢幕閱讀器、RWD 與 LINE safe area 是元件驗收條件。

## 2. 會員導覽

固定順序為：**首頁 → 點數兌換 → AI → 服務 → 會員中心**。

桌機使用頂部導覽；手機使用底部主要導覽。兩者路由與語意一致，不維護兩套功能。AI 可切換到指定頁面，但不得在沒有告知的情況下改變資料。

## 3. 首頁資訊順序

1. 點數餘額與本月已消費金額。
2. 待處理事項：待確認、即將履約、取貨、到期優惠與提醒。
3. 輕量 AI：一行交辦及最近任務入口，送出後進入完整 AI 頁。
4. 個人推薦：服務、商品或優惠，顯示推薦理由與限制。
5. 常用功能：由實際行為產生，無資料時提供少量新手捷徑。
6. 活動／廣告：明確標示推廣，不搶在待處理事項之前。

推薦的「不感興趣」只作用於該卡片及合理相似項目，操作後提供復原；不允許關閉整個推薦區。過敏與禁忌是硬性排除，和不感興趣分開。

## 4. 點數兌換

點數頁不是活動型錄，包含：

- OPENPOINT 餘額、即將到期點數及來源。
- 可用優惠券、分享券與即將到期項目。
- 點數／優惠券／支付方式試算，顯示使用前、折抵及應付金額。
- 兌換與使用紀錄。
- 可由 AI 以自然語言試算，例如「這筆清潔怎麼折最省」。

正式 API 尚未取得時使用有來源標示、可重算的競賽帳本，不宣稱即時 OPENPOINT 餘額。

## 5. 全頁 AI

### 5.1 版面與捲動

- 對話頁高度以可視 viewport 計算；頁首與輸入區外的內容不造成整頁雙重捲動。
- 訊息清單是主要捲動容器，滑鼠位於訊息內容、卡片或空白處時都能使用滾輪。
- 輸入區固定在聊天頁底部，不因訊息變長被推離可視範圍。
- 使用者訊息置右，AI 訊息置左；不可只用顏色區分角色。
- 新訊息在使用者已接近底部時自動跟隨；若使用者正在閱讀舊訊息，不強制拉到底，改顯示「回到最新訊息」。

### 5.2 輸入框

- 使用 `<textarea>`，CSS `resize: none`，不提供滑鼠拖曳控制點。
- 單行起始，依內容與換行自動增高；到設定上限後 textarea 內部捲動。
- `Enter` 送出、`Shift+Enter` 換行，並提供可見提示及可點擊送出按鈕。
- IME 組字期間不得誤送；空白訊息不可送出。
- 聚焦、錯誤、停用及語音錄製狀態皆有文字或可存取名稱。

### 5.3 選項與可操作回覆

- AI 有候選答案時，在輸入區正上方顯示 button／radio／checkbox 選單，不把選項埋在純文字條列。
- 服務推薦卡提供「查看方案」「選擇」「不感興趣」等真實操作。
- 單選可立即填入並等待送出，或在低風險澄清時直接提交；多選保留明確確認。
- 所有控制項支援 Tab、方向鍵（適用時）、Enter／Space 與可見焦點。

### 5.4 Streaming 與等待體驗

- 串流呈現回覆文字、目前階段及工具活動，例如「正在確認服務範圍」「正在比較 3 個方案」。
- 長操作顯示開始、進行中、完成／失敗及可重試，不讓使用者只看到無限 spinner。
- 可折疊顯示的是**執行摘要與依據**：使用了哪些資料、呼叫哪些工具、為何需要確認。
- 不揭露模型原始 chain-of-thought、隱藏 prompt、憑證或個資。
- 串流區使用適當 `aria-live`，避免每個 token 都打斷螢幕閱讀器；完成後提供一次完整宣告。

### 5.5 全系統掌握

AI 使用 capability registry 取得功能、參數、權限與目前可用性。它可以：

- 查詢點數、優惠、推薦、服務、群組與訂單。
- 導航到指定頁面或展開指定訂單。
- 準備提醒、偏好、群組共享與諮詢表單預覽。
- 試算點數及比較廠商方案。
- 經確認後建立訂單、接受報價、兌換或取消。

AI 不可宣稱不存在的工具已執行，也不可把自然語言回覆當作交易成功。

## 6. 服務頁

- 支援自然語言搜尋、分類、常用、情境及替代方案。
- 「想找人打掃」優先顯示清潔相關候選；低信心時先澄清，不把整個目錄當辨識結果。
- 每張服務卡至少能查看方案、填寫需求、建立諮詢／訂單或追蹤狀態之一。
- 題組來自官方 `pms_form_topic.type` 支援的 schema；已知會員資料不重問，使用前顯示用途。
- 廠商比較呈現服務範圍、可用時段、價格、評分、理由及不符合條件的代價。

## 7. 訂單與履約

- 訂單依「待確認、進行中、待取件／到場、已完成、異常」分組。
- 各組及訂單列可折疊；預設展開當前最需要處理的群組，不讓長列表淹沒頁面。
- 摘要顯示服務、廠商、編號、下一步與更新時間；展開後才顯示完整時間軸、金額與客服入口。
- AI、首頁與訂單頁顯示同一後端狀態，不各自維護 fixture。
- 訂單異常提供重試、替代方案、建立客服工單或聯繫廠商，不只顯示錯誤碼。

## 8. 會員中心與群組

- 個人資料、地址、聯絡方式及模擬 uniopen 身分。
- 行為個人化同意、推薦偏好、過敏／禁忌及資料清除。
- 家庭、情侶、宿舍與社區群組；顯示成員角色、共享範圍及通知設定。
- 會員可加入多個群組，切換 active scope 時清楚顯示目前代表自己或哪個群組。
- 群組代辦、需求聚合及安心通知需明確授權並保留稽核。

## 9. 身分與入口

- 會員登入使用可替換的 uniopen identity adapter；競賽期間可用種子帳號，但語意是登入，不是 demo 角色切換。
- 廠商後台使用獨立入口與權限，不出現在會員頁籤。
- 平台營運後台同樣分離，Demo 可用明確的主持人入口切換，不放在一般會員 UI。
- 新會員真的是零資料；零狀態負責教學，不借用別人的消費或訂單填畫面。

## 10. 驗收

- [ ] 新會員 60 秒內能理解產品並完成第一次 AI 交辦。
- [ ] 聊天輸入區始終可見，textarea 自動增高且不可手動 resize。
- [ ] 長對話只捲動訊息區，滑鼠不需移到外側。
- [ ] 選項是可操作控制項，推薦及服務不存在純展示死卡。
- [ ] 不感興趣不會關閉全部推薦，且可復原。
- [ ] 訂單分組與明細可折疊，鍵盤及螢幕閱讀器可操作。
- [ ] 交易、高影響設定及群組共享皆有預覽、確認及稽核。
- [ ] 390×844、1440×900、200% zoom 與鍵盤流程通過 WCAG 2.2 AA 基線。
