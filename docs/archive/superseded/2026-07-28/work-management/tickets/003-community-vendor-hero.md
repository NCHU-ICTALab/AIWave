# 社區與廠商 Hero 深化

- 類型：task（AFK）
- 狀態：完成
- 阻擋：[九項服務題組與報價規則](001-service-forms-and-pricing.md)

## Question

如何把 DUSKIN 冷氣聯合清洗補成需求統計、AI 草稿、兩案比較、報價分項、指派與履約事件完整閉環？

## 已確認的實作契約

- 同一筆 `joint_service_campaign` 貫穿管委會與廠商工作台，不以兩份前端 fixture 模擬跨角色流程。
- 狀態機為 `draft → collecting → proposal_review → assigned → in_progress → completed`；不得跳級。
- Hero 種子包含 18 戶、27 台冷氣的匿名需求證據與兩份可比較的分項方案。
- 管委會必須先看到價格、可服務時段、優點與限制，再二次確認指派；AI 只能產生草稿與比較說明。
- 廠商只能看已指派給自己的標準化工單，並依序回報開工與完工；所有變更寫入事件時間軸。
- DUSKIN 名稱只描述公開服務情境；住戶需求、時段、報價與評分均標示為「競賽建置資料，非品牌即時報價」。
- HTTP、站內 Agent 與 MCP 共用 `core/community/joint_service.py` 的規則，不在傳輸層複製商業邏輯。

## 驗收情境

1. 管委會看到 18 戶／27 台需求、來源與偏好分布，並比較至少兩案的分項報價。
2. 未確認前不會指派；確認 A 案後，B 案不可再被指派，事件新增 `joint_service.assigned`。
3. 合作廠商工作台立即出現同一案件，可依序開工、完工並留下說明。
4. 管委會重新載入後看到相同狀態與事件，不因切換角色而重置。
5. 住戶、管委會、合作廠商的工具權限互斥；工具參數不得接受 `account_id` 或 `role`。
