## 1. 為什麼用自動駕駛，而不是手動操作

手動錄一次要五分鐘，重錄一次也要五分鐘，而且每次節奏都不一樣——旁白稿對不上第二次的畫面。
自動駕駛之後：

- **單幕重錄只要幾十秒**：`--only=6` 會先無停頓快轉前五幕把狀態補齊，再用正式節奏錄第六幕。
- **第 N 次跑出來的畫面和第 1 次一樣**：秒數、捲動位置、打字速度都固定。
- **配音有東西可對**：每次跑完輸出 `tmp/demo-cues.md`，列出每一幕的進入時間與實際長度。

腳本只負責**操作與節奏**，不錄影、不發聲。錄影交給 OBS，旁白後製配。

## 2. 兩條硬限制（改腳本前必讀）

| 限制 | 出處 | 對錄影的影響 |
| --- | --- | --- |
| `CommunityDemoService` 的狀態是模組內記憶體，**整頁重載就洗回 seed** | [`communityDemoService.ts:51`](../../web/app/src/services/communityDemoService.ts#L51)、`resetDemo()` | 開場之後一律走 SPA 內部導覽；全程只有一次 `goto`。中途重載＝剛開的團消失。 |
| `DemoRoleSwitcher` 只在 `/demo/*` 路徑渲染 | [`DemoRoleSwitcher.vue:28`](../../web/app/src/components/DemoRoleSwitcher.vue#L28) | 主線必須待在 `/demo/*`。換角色只能用畫面右上的切換器，不能改 localStorage 再重載（那會觸發上一條）。 |

反過來說，這也帶來一個對備援影片很有利的性質：**九幕走的全是前端 Demo 資料**——
不需要後端、不需要 LLM、不需要網路。只要 `npm run dev` 起得來就錄得成。
（`問社區` 那段畫面上就寫著「不呼叫外部 LLM・Demo Wiki」，不是隱瞞，是明講。）

## 3. 錄製前準備

```bash
# 只需要這一個服務
cd web/app && npm run dev
```

OBS 設定：

1. 來源選 **視窗擷取**，抓 Chromium 視窗（腳本會固定開在螢幕左上角）。
2. 畫布 1280×720（腳本預設；要 1080p 就跑 `--size=1920x1080`，OBS 畫布跟著改）。
3. 腳本已用 `ignoreDefaultArgs: ['--enable-automation']` 移掉「Chrome 正受自動測試軟體控制」
   的黃色橫幅，畫面上不會出現它。

## 4. 九幕分鏡

總長 **3:46**。「畫面必須出現」是驗收條件——如果某一幕靠旁白才講得清楚，那一幕就是失敗的。

| # | 幕 | 長度 | 路徑 | 操作 | 畫面必須出現 |
| --- | --- | --- | --- | --- | --- |
| 1 | 登入與社區首頁 | 22s | `/login` → `/demo/resident` | 點「以住戶王小明進入」 | 社區快訊跑馬燈（公告與熱銷團購交錯輪播）、2 件待領包裹、電梯保養公告、報修進度、進行中團購四張 KPI |
| 2 | 問社區・垃圾車 | 24s | `/demo/resident` | 逐字輸入「垃圾車幾點來」→ 送出 | 思考狀態 → 答案 → **來源標註** → 相關問題 |
| 3 | 問社區・假日裝修 | 20s | 同上 | 點快捷問題 | 平日／週六／週日與國定假日三組規則分開 |
| 4 | 社區優惠與訂閱回饋 | 18s | 同上 | 點價格問號 | 市價 NT$3,800 vs 社區價 NT$3,500、價差來自訂閱回饋的說明 |
| 5 | 主委發布團購 | 24s | → `/demo/committee` | 切主委 → 發布杜拜巧克力 | 可逐欄修改的商業條件、發布後回饋訊息、初始進度 7/10 |
| 6 | 住戶跟團 | 48s | → `/demo/resident/group-buy/:id` | 切住戶 → 開巧克力 → 選六入 → 我要 +1 | 進度 7/10 → **8/10**、我的訂單 六入 × 1 |
| 7 | 主委看訂單彙總 | 24s | → `/demo/committee` | 切主委 | 王小明・A 棟 12F-3・六入 × 1・**NT$780**、成交額 KPI 同步 |
| 8 | Wiki 管理 | 18s | 同上 | 標記一則未回答問題 | 查詢排行、最新問題、未回答清單與「待補充」狀態變化 |
| 9 | 訂閱與帳務 | 28s | → `/demo/subscription` | 點訂閱 CTA | 28 戶落在 1–30 戶級距、月費 NT$999、導入期免費試用 3–6 個月、住戶省下 NT$4,620、社區淨效益 +NT$3,621 |

### 長度是怎麼定出來的

以機器能跑的最快速度，九幕只要 **53 秒**就走完——**畫面遠比旁白短，不處理的話配音會追不上畫面**。
所以腳本做兩件事：預設節奏放慢到 `--pace=2.6`，跑完再把每一幕**補到上表的秒數**。

因此每一幕的長度是「旁白唸完所需時間」與「動作本身的自然長度」取大者：

- 第 1–5、7–8 幕由**旁白**決定（中文約 4–5 字／秒，加換氣）。
- 第 6、9 幕由**動作**決定——第 6 幕要切角色、開商品、選規格、跟團、看進度變化，
  在 `--pace=2.6` 下自然就要 46 秒，比旁白長。

補時只能把幕拉長、不能縮短，所以**預算必須不小於動作的自然長度**，否則
「總長 = 預算總和」就不成立、分軌表的進入時間會飄。腳本跑完會自己檢查並列出超時的幕。
上表的數字都是 `--pace=2.6` 的實測值，總長 3:46。要改長度就改 `SCENES` 裡的 `budget`
（改短到低於動作長度不會生效，腳本會警告）。

**這條主線的論證結構**：1–4 證明住戶端每天真的用得到（資訊集中、問得到答案、看得到優惠）；
5–7 證明**同一份資料的雙視角**（住戶送出 → 主委立刻看到，不是兩套系統對帳）；
8–9 把它收到商業模式上（知識庫會長大、訂閱費變成住戶看得見的優惠）。
第 6→7 幕是全片的核心證據，重錄時優先保這一段的節奏。

## 5. 錄製指令

```bash
cd web/app

node tools/demo-drive.mjs --list                # 先看九幕與長度
node tools/demo-drive.mjs --countdown=5         # 正式錄：每幕開始前倒數 5 秒給你按 OBS
node tools/demo-drive.mjs --only=6              # 只重錄第 6 幕（前五幕自動快轉補狀態）
node tools/demo-drive.mjs --from=5 --to=7       # 重錄核心段
node tools/demo-drive.mjs --pace=3.2            # 動作再慢一點（預設 2.6）
node tools/demo-drive.mjs --slate               # 彩排用：幕間顯示場記板（正式錄請關）
node tools/demo-drive.mjs --video               # 另存一份 Playwright webm，當備援的備援
node tools/demo-drive.mjs --nofill --pace=0.12  # 只驗證腳本跑不跑得通（約 11 秒，不是錄影用）
```

跑完會在 repo 根目錄產生 `tmp/demo-cues.md`：

| 幕 | 進入時間 | 實長 | 預算 | 旁白 |
| --- | --- | --- | --- | --- |
| 6. 住戶跟團 | 2:51 | 48.6s | 50s | 切回住戶。杜拜巧克力已經出現… |

配音時直接對這張表的「進入時間」。

腳本會監看 console error 與 4xx/5xx；**有錯誤時 exit code 非 0 並列出前 10 筆**——
代表那一次的畫面可能有破綻，建議重錄。

## 6. 分段錄製的接法

九幕各錄一段，最後接起來。這樣任何一幕不滿意只需要重錄那一幕：

```bash
ffmpeg -f concat -safe 0 -i clips.txt -c copy demo-full.mp4
```

`clips.txt` 每行一個 `file 'scene-01.mp4'`。用 `-c copy` 直接串流複製，不重壓、不掉畫質；
前提是九段的解析度／幀率／編碼一致——只要都是同一組 OBS 設定錄的就會一致。

## 7. 已知邊界（錄影時不要宣稱的事）

- 九幕使用的是**前端 Demo 資料**（`communityDemoSeed.ts`），不是後端 SQLite 或官方訂單。
  這一段不能講成「真實交易閉環」——真實閉環在 `/user/*` 那條線，走的是後端與真 LLM。
- 「問社區」不呼叫外部 LLM，畫面上自己有標。不要在旁白裡把它講成 AI 生成。
- 訂閱金額、分潤比例、住戶省下金額都是 `competition_seed` 等級的競賽建置資料，
  不是統一集團的正式報價。住戶端 `/user/subscription` 與這裡讀同一份 seed，
  兩邊的月費一定一致；但**社區訂閱只做到前端狀態，沒有後端授權與計費**，
  旁白不要講成「已上線的訂閱制」。
- 團購卡片上的商品名稱、品牌與規格是真的統一企業商品（有原商品頁連結可查），
  卡片圖是**零售通路（momo 購物網／全聯線上購 PXGo）自己拍的商品照片**，一次下載後放在
  `web/app/public/group-buy/*.jpg` 由本站提供，執行時不連外部 CDN；同資料夾的 `README.md`
  逐張記下商品、照片來源網址、卡片連結與取得日期，卡片上的「查看原商品頁」就是出處。
  自繪的 `*.svg` 只是照片載入失敗時的備援。這些照片**不是統一企業授權的官方素材，
  本專案也沒有與統一企業合作**——旁白不要說「官方商品圖」或暗示品牌合作。
  價格、庫存、到貨日與成團進度全是 Demo 資料。
- 若要另外錄「真 LLM 對話」片段（`/user/assistant`），那需要後端與 `.env` 的
  NCHC Gemma 都在線，而且延遲不可控——**建議獨立錄成一段補充影片，不要接進這九幕主線**，
  否則斷網備援影片就不再是斷網可用的了。
