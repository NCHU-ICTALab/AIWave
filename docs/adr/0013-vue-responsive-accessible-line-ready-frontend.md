# Vue 前端從第一天落實 RWD、WCAG 2.2 AA 與 LINE WebView 相容性

Web 是競賽版主要產品與 Demo 介面，LINE 則是後續可接入的延伸通路。若先只做桌機版，再於末期補手機與無障礙，導覽、資料表、固定操作列、表單錯誤與互動元件通常都需要返工，也容易讓 LINE 內開啟成為另一套特例。

我們決定前端採 **Vue 3＋Vite SPA**，以共用設計 token 與基礎元件同時承擔四個工作區。所有 P0 流程從開發初期即須在桌機、手機與 LINE WebView 情境可完成，並以 **WCAG 2.2 AA** 作為驗收基線。一般內容須在 320 CSS px 寬度重排而不遺失資訊或功能；底部固定操作需處理 safe area；LIFF/LINE SDK 能力封裝在獨立 adapter/composable，使同一頁面在一般瀏覽器仍能工作。

無障礙不限定單一視覺風格：所有候選設計都必須符合文字與非文字對比、鍵盤操作、可見焦點、語意結構、表單標籤與錯誤、狀態公告、文字縮放及減少動態。WCAG 2.2 AA 的指標目標最低為 24×24 CSS px；本產品的主要觸控操作採 44×44 CSS px 作為設計目標，以改善手機、樂齡與 LINE 內使用體驗。

此決策的代價是元件開發與視覺探索初期需要多做響應式及無障礙驗證；換來的好處是後續接入 LIFF 不必重寫主要流程，且五種視覺方向能在相同可用性門檻下公平比較。
