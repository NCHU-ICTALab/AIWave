# 修繕、跟團、公設預約三流程共用一套題組引擎

官方強調「諮詢單＝問卷形式、彈性題組設計、題目可延伸」。我們決定：不為每種服務寫死對話流程，而是做一套讀取官方表單 schema（`pms_form` → `pms_form_group` → `pms_form_topic` → `pms_topic_option`）的題組引擎，由 LLM 逐題引導填答；修繕諮詢、團購跟團、公設預約三種流程共用引擎，只在收單後的「落地流程」分岔（→ 諮詢單／跟團訂單／公設預約單）。

跳題邏輯不改官方 DDL，利用 `pms_form_topic.feature`（JSONB）擴充 `skipLogic` 設定。

## Considered Options

1. **共用引擎（採用）**——「新增一個服務＝新增一份題組定義，零程式碼」，直接對應官方的彈性題組訴求，也是 demo 的招牌橋段。
2. 只有修繕走題組、其餘寫死流程——工時最省，但延伸服務就要改程式，彈性題組的故事不成立。
3. 自訂全新表單格式不沿用官方 schema——設計自由，但放棄了與官方資料集的直接銜接。

## Consequences

- 新服務上線的成本 ≈ 寫一份題組 JSON；demo 可現場載入「公設預約」題組讓 Agent 立刻支援新服務。
- 引擎必須涵蓋官方題型（簡答、單選、複選含雙層子選項、地區選單、上傳圖片、聯絡資料）加上擴充題型（數量、日期時段），複雜度集中在引擎一處。
- 語音（樂齡）與文字共用同一份題組定義，只是呈現層不同。
