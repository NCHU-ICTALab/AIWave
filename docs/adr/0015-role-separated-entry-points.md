# 角色分離入口與登入身分，取代工作區切換器

原本四個角色（住戶／社區管理者／合作廠商／平台營運）共用同一個畫面殼，靠頂端下拉切換。
這讓產品看起來像一組後台工具，而不是一個使用者會用的 app——真實使用者只會是其中一種身分。

決定改為：`/login` 選擇身分後，進入 `/user`、`/admin`、`/partner` 各自的介面；
移除工作區下拉與「重設」按鈕。同時，**demo 資料的豐富度改由「登入成哪個帳號」決定**，
而不是靠一個展示開關：新帳號真的是空的（由零狀態負責教學），官方訂單資料中的帳號則是
「已經用了一陣子的使用者」。

平台營運（`/platform`）依先前決定屬後續加分，路由保留但不列入登入選項與主導覽。

## Considered Options

1. **角色分離入口（採用）**——真實產品就是這樣分的（Uber 與 Uber Driver 是兩個 app）。
   demo 時「切到另一個入口」比「切下拉」更像真的產品，也讓每個畫面能專心回答
   「這個身分現在該做什麼」。
2. 保留單一下拉但標示為「展示用角色切換」——誠實，但仍然把展示裝置留在使用者面前，
   初次到訪者還是會困惑自己是誰。
3. 完全不分角色，只做住戶端——最乾淨，但命題明文要求呈現消費者／廠商／管理後台三種角色。

## Consequences

- 需要「目前身分」的概念。競賽期間以輕量假登入實作，但**語意是登入而非 demo 切換**；
  日後接 OIDC 只換取得身分的方式，畫面與路由不變。
- 新使用者會看到空畫面，因此**零狀態變成必要的設計對象**（見
  [08 產品體驗](../specs/08-product-experience.md) §6），不能再靠預載假資料掩蓋。
- 既有掛載 `App.vue` 的元件測試需改為先設定身分再進入對應路由。
- [05 Web 工作區模組](../specs/05-erp-modules.md) 與
  [07 Demo 垂直切片](../specs/07-demo-vertical-slice.md) 以「單一平台四工作區」為前提，
  需回填為角色分離入口。
