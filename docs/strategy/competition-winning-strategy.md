## 1. 一句話定位

> **AIWave 是會關心會員生活、並在取得同意後把事情做到底的 AI 生活管家。**

它不是第二個 OPENPOINT、第二個社區管理 App、服務型錄或 ChatGPT 包殼。AIWave 位於點數、服務、社區與 Provider 之上的編排層，將生活情境與自然語言目標轉成可編輯、可授權、可履約及可追蹤的生活任務。

## 2. 競賽論述順序

不要從模型、MCP 或 AWS 開始。以下是功能完成驗收後的目標敘事，不是目前能力清單；未通過程式、測試與 Demo runbook 的項目不得使用完成式。評審應依序理解：

1. **[合理推導，待訪談驗證] 會員可能難以把跨服務生活目標走完。**
2. **AIWave 先讓可重用的服務、交易與履約底座通過 Demo 驗收。**
3. **目標中的自然 Agent 讓會員用自己的說法規劃、比較、修改與反悔。**
4. **目標中的主動關懷與生活指南把需求發現提早，但仍由會員決定是否行動。**
5. **競賽版只在 Provider 完成履約後顯示 Demo 成功服務費投影；正式收入模式待合約與會計驗證。**

可記憶工作流：

```text
看見生活 → 理解目標 → 編輯任務 → 一次授權 → 履約到底
```

## 3. 三個招牌能力

**[待實作／待驗收]** 以下是主 Demo 的目標能力組合；現有可重用模組不等於整段體驗已完成，只有通過相應測試與 runbook 後才能改列為現場證據。

### 3.1 可信的生活服務底座

手動服務探索、點數試算、Booking／Order、Provider 工作台、`StatusEvent`、通知及行事曆先構成閉環。Agent、Web 與未來 MCP 共用同一份資料，不在前端演假流程。

### 3.2 自然但可控的 Agent

LLM 真正負責多輪理解、上下文承接、工具規劃與 grounded 解釋，而不是只抽固定欄位。會員可以聊天、詢問、比較、修改、反悔或開始新 Session。確定性平台仍掌管 capability、Provider、時段、價格、點數、權限、授權、狀態與冪等。

自然回覆與權威卡片分工：模型可以說人話；卡片保證數字與操作可靠。

### 3.3 從生活情境到協助式商務

有原因與來源的提醒可開啟情境式生活指南，再轉成通用準備清單、會場／社區 N 分鐘生活圈、Catalog 商品與 TaskDraft。推播先提供價值；會員點「幫我準備」後才看商品與服務，不以焦慮逼迫消費。

## 5. 為什麼這個 Demo 有辨識度

- **先基礎再創新**：評審知道 AI 建立在真服務閉環上。
- **會場生活圈**：展示起點就是比賽現場，不需要抽象解釋。
- **自然 Agent**：用同義改寫、上下文修正與新對話，直接對比模板機器人。
- **中元指南**：具有台灣生活辨識度，同時展示來源治理、清單與商務轉換。
- **成就提示**：只作完成瞬間，不用複雜遊戲化搶主故事。
- **Provider 結算**：Demo 費用投影只在履約完成後出現；正式收入模式待合約與會計驗證，不靠廣告敘事硬湊商業模式。

## 7. 北極星與量測

### 主指標

- **生活任務完成率**。

### 次指標

- 從描述需求到確認方案的時間。
- 生活情境 → 指南 →「幫我準備」→ 確認任務轉換率。
- Provider 接單率與履約完成率。
- 完成交易金額與成功服務費。

### 信任護欄

- 未經授權交易：0。
- 無來源生活回答率。
- 任務人工修正率。
- 關懷忽略／關閉率。

不把聊天次數、停留時間、推播點擊或成就解鎖數當北極星。

## 8. 商業敘事

主報告只保留以下目標商業敘事：

1. 消費者端目標維持免費。
2. 競賽版只展示完成後的 Provider 成功服務費投影；正式版才假設 Provider 為已釐清需求、預算與時段的可履約訂單支付成功服務費。
3. 活動回饋未來可由品牌／Provider／平台贊助，競賽版為模擬。

正式收費是否成立、Provider 合約、費率、預算池、贊助分攤、會計與退款沖銷都待官方或訪談驗證，僅放附錄。會員端不顯示抽成；Provider／平台端只看 Demo 成交金額、Demo 服務費、示意贊助與預估淨額。

## 9. 誠實邊界

- 固定 GeoJSON、fake upstream、Demo points、費率、贊助與 seed 都不等於正式合作或即時資料。
- Amazon Location 只有在 IAM、台灣覆蓋、結果品質、成本、延遲與限制完成驗證後，才是選配／正式方案。
- 中元、颱風、搬家指南須有官方或授權來源；第三方產品只作形態參考。
- 不把推薦說成必要，不以宗教、災害或家庭焦慮促銷。
- 不做背景定位、秘密購物車或未授權交易。
- 不展示 hidden chain-of-thought；只顯示可驗證進度、工具依據與結果。
- 不把 Steam 式成就提示宣稱為核心產品價值。

## 10. 取捨清單

### 主 Demo 必須有

- 基礎手動閉環。
- FAQ Wiki。
- 會場 10 分鐘生活圈。
- 自然多輪 Agent 與 Session。
- 可編輯任務包與一次授權。
- Provider 回流。
- 中元生活指南短場景。
- 生活成果、成就提示、回饋與結算。

### 主 Demo 不做

- 完整提醒設定。
- 第二套完整情境下單。
- Group／Community 管理流程。
- MCP 現場操作。
- 大型 RAG／向量庫。
- XP、等級、排行榜與角色養成。
- 正式定位追蹤與導航。

## 11. Q&A 一句答法

| 問題 | 一句回答 |
| --- | --- |
| AI 為何比一般聊天更有用？ | 它不只回答，還能在會員授權後用同一套平台能力把任務履約完成。 |
| 為何比一般 Agent 安全？ | LLM 可自由理解與解釋，但價格、權限、時段、點數與交易由確定性平台裁決。 |
| 為何需要 Session？ | 會員可以自然延續一個生活目標，也能隨時開乾淨新對話而不刪除正式任務。 |
| 為何不用 RAG？ | 競賽內容量小，兩個經審核 Wiki 全量 context 更簡單可控；規模增加再升級。 |
| 如何兼顧消費與信任？ | 先提供有用提醒與指南，會員主動要求準備後才呈現商品、服務與合作推薦。 |
