# AIWave 競賽策略與奪冠證據

> 狀態：現行策略基線  
> 更新日期：2026-07-28  
> 適用範圍：產品取捨、Demo、簡報、技術架構與商業敘事

## 1. 一句話定位

> **AIWave 讓會員只需說出生活目標，AI 就能跨點數、廠商與群組完成規劃、比較、確認、派單與追蹤。**

AIWave 不是第二個 OPENPOINT，也不是第二個社區管理 App。OPENPOINT 提供帳號、點數、優惠、品牌與服務資產；社區平台處理管理費、公告、包裹、門禁與公設等社區營運；AIWave 位於兩者之上，負責把會員想達成的結果編排成可執行、可確認、可追蹤的生活任務。

## 2. 從 2025 各組優勝作品歸納出的六項規律

去年七隊是不同企業命題組的優勝，不是同一個總冠軍。跨命題仍重複出現的特徵，才是本專案應採用的競賽規律。

| 規律 | 得獎作品的共同做法 | AIWave 必須呈現的證據 |
| --- | --- | --- |
| 痛點先於技術 | 先說明具體使用者、既有流程與失敗成本 | 開場是跨 App、重複填答、無法比較、無人追蹤，不從 LLM/MCP 開始 |
| 一條可記住的工作流 | 以 3–5 個功能或階段說完整故事 | 理解目標 → 拆解任務 → 試算與媒合 → 一次確認 → 履約追蹤 |
| AI 改變工作方式 | 語音觸發任務、文字轉結構規格、雙 LLM 分工 | AI 能規劃並呼叫工具，不只是聊天、分類或填表 |
| 命題方資產進入核心決策 | 真正使用企業資料、設備或 API | 官方訂單、題型、地區資料及統一生態服務真正影響推薦與執行 |
| 信任機制可見 | RAG、指標、加密、版本、身分與記憶控制 | 權限分級、來源、確定性試算、稽核、故障降級與個資隔離能被展示 |
| 有產品及商業閉環 | 可跑原型、擴展方式、營收或導入方式清楚 | 從會員需求到廠商履約完成；說明轉換率、媒合成本、群組聚合與接入效率 |

## 3. AIWave 的三個招牌能力

### 3.1 生活目標編排

會員使用自然語言描述想完成的結果。AI 保留上下文、辨識多意圖、拆成有順序的任務，並只追問缺少且會影響執行的資料。

### 3.2 跨服務最佳方案

同一個方案同時考慮服務類型、廠商服務範圍、時段、預算、緊急程度、評分、點數、優惠券、群組需求與使用者限制。價格、點數與狀態由規則計算；LLM 負責理解、規劃與解釋。

### 3.3 確認後執行到底

AI 不把一張推薦卡當成完成。讀取與導覽可直接進行；設定與留資產生預覽；下單、兌換、報價、取消等高影響操作必須確認。確認後透過平台 API／MCP 建立任務、持續追蹤並在上游失敗時提供可理解的恢復方案。

## 4. 代表性 Hero Demo

> 「爸媽週六要來，浴室燈壞了、冷氣也很久沒洗，幫我安排一下，OPENPOINT 能省就省。」

固定展示五步驟：

1. AI 解析為水電修繕、冷氣清洗與點數試算三個相依任務。
2. 系統套用會員地址、家庭範圍、時段及個人偏好，缺少的資料以聊天框上方按鈕補齊。
3. 比較王子水電與適合的清潔方案，顯示價格、時段、服務範圍、點數及取捨理由。
4. 會員一次預覽並確認；平台透過獨立 fake vendor server 建單，廠商端收到案件。
5. 廠商更新狀態，會員在 AI 與訂單頁看到同一份進度；現場可注入一次逾時，展示降級、重試與稽核。

群組槓桿是差異化加碼：經會員明確同意後，可詢問家庭或社區是否有相同需求，聚合成較佳價格或共同時段，但不強迫加入、不洩漏個人資料。

## 5. 與相鄰平台的邊界

| 平台 | 核心價值 | AIWave 的關係 |
| --- | --- | --- |
| OPENPOINT | 帳號、點數、優惠、支付與統一品牌服務入口 | 使用其生態資產完成跨服務任務，不重做點數平台 |
| 智生活類社區平台 | 管理費、公告、包裹、門禁、公設、物業與設備整合 | 未來作為 `CommunityConnector`，不重做社區基礎設施 |
| 單一服務商 App | 完成單一品牌的預約、購買與履約 | 透過 `VendorClient`／MCP 編排成跨廠商任務 |
| AIWave | 個人目標驅動的跨品牌、跨廠商、跨群組任務編排 | 保持會員為主體，群組是可選的協作與需求槓桿 |

[智生活指定文章](https://www.smartdaily.com.tw/col-ai-gov-smart-community-lifestyle-ecosystem/)及其[官方產品現況](https://www.smartdaily.com.tw/)證明社區管理、AI 客服與生活服務入口已是成熟方向。本文只把它當成市場邊界、導入經驗與未來 connector 參考，不把其功能清單直接加入 AIWave roadmap。

## 6. 評審必須看見的可量化證據

Demo 前先量測基準流程，再呈現 AIWave 結果；不預先填入未經測量的宣傳數字。

- 完成同一生活目標所需的 App／頁面切換數。
- 使用者必須手動輸入的欄位數與重複欄位數。
- 從描述需求到取得可確認方案的時間。
- 點數及優惠實際節省金額，且每個數字可重算。
- 廠商接入後被 Web、AI 與 MCP 共用的能力數。
- 上游逾時或錯誤時，是否仍能完成可用的替代流程。

## 7. 商業飛輪

```text
會員更容易完成生活任務
  → 更多可結構化需求與服務轉換
  → 群組需求聚合、降低廠商獲客成本並提高排程利用率
  → 更多廠商以標準契約接入
  → 方案更完整、點數與統一生態使用率提高
  → 累積未滿足需求，形成招募廠商與設計新服務的情報
```

## 8. 明確不做

- 不以功能數量作為主要競賽論述。
- 不重做 OPENPOINT 的完整支付、點數或品牌活動平台。
- 不重做社區管理費、門禁、包裹、公告或硬體管理。
- 不宣稱 fake server 是正式合作 API。
- 不展示模型的原始隱藏推理；只呈現對使用者有用的進度、工具操作、依據與結果。
- 不讓尚無後續操作的推薦或服務卡片出現在主要流程。
