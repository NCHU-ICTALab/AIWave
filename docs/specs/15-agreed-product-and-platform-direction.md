# AIWave 產品與平台定案基線

> 狀態：現行且具最高優先級  
> 定案日期：2026-07-30；v4 決策同步：2026-08-01
> 適用範圍：產品、Web、後端、Agent、MCP、廠商 API、fake server、測試與部署  
> 若其他文件與本文件衝突，以本文件為準；v4 主動生活管家與自然對話的更具體定義分別以 [16](16-proactive-life-butler-and-commercial-loop.md) 與 [17](17-conversational-agent-session-and-llm-wiki.md) 為準。尚未完成的功能不因寫入文件而視為已實作。

## 1. 產品定義

AIWave 是一個以個人會員為主體的生活服務作業系統。它把分散的服務、點數、行程、通知、群組與社區情境放入同一個可追蹤的任務流程，並讓使用者選擇手動操作或交由 Agent 協助。

v4 對外定位是：**AIWave 是會關心會員生活、並在取得同意後把事情做到底的 AI 生活管家。**

AIWave 不是第二個 OPENPOINT、純聊天機器人、服務型錄、社區管理 App，也不是只有畫面的 mock demo。差異化在於：

1. 同一件生活目標可跨服務拆解、安排、確認、執行與追蹤。
2. 手動流程、Agent、MCP 與廠商後台操作的是同一份資料和狀態機。
3. LLM 主導自然對話、語意理解、規劃與解釋；金額、權限、時間、服務存在性及訂單狀態由確定性規則守門。
4. Agent 可從生活情境與可信指南提出協助，但只有會員同意後才建立任務或交易。
5. 廠商即使沒有既有 API，也能透過公開契約、Adapter 或工作台加入生態。

## 2. 服務範圍與完成深度

**[待官方或訪談驗證]** 目前依競賽材料整理的生活場景為食、醫、住、行、預、樂；說明會另列外送、訂位、清潔、修繕、宅配、購物、影音、領藥，書面命題包含 App 叫車。對外引用前必須補上官方命題／說明會來源；來源確認前只作範圍規劃，不當成已驗證企業事實。類別可擴充，不把產品寫死為固定六格或八格。

### 2.1 閉環定義

一個服務只有同時具備以下第 1–7 項，才能宣稱「Demo 基礎履約閉環」：

1. 使用者能從服務頁手動開始，不必依賴 Agent。
2. 有真實可操作的選項、表單驗證與後端資料。
3. 依服務類型選擇店家、方案、資源／人員與真實可用時段。
4. 使用者確認後建立訂單、預約或諮詢單。
5. 合作方或 fake upstream 能收到並回覆。
6. 使用者端能看到由履約事件驅動的進度條、通知與行事曆變化。
7. 至少有一條可恢復的失敗路徑，且重新整理、上一頁與重試不會破壞狀態。
8. 若要進一步宣稱「完整平台閉環」，同一能力另須能被 Agent 與 MCP 操作，且權限與確認規則一致。

MCP 不進五分鐘主 Demo，因此 Demo 可在第 1–7 項通過驗收後宣稱「Demo 基礎履約閉環」，不得因此宣稱第 8 項或完整平台閉環已完成；MCP 僅在後續實作與測試通過後納入完整平台證據。

### 2.2 優先順序

| 優先級 | 內容 | 目標 |
| --- | --- | --- |
| P0 | 住：清潔、修繕；食：訂位；預：購物／i 預購 | 各至少一個完整閉環；住做最深 |
| P1 | 行：叫車；樂：影音／娛樂；外送；宅配 | 以共用核心擴充成可執行閉環 |
| P2 | 醫：處方箋辨識＋藥局連結／領藥；語音 | 時程允許才做；未完成不得顯示可點入口或對外宣稱 |
| 延後 | LINE／Discord、正式 AWS 最終架構 | Web 完整且穩定後再做 |

真實廠商、服務欄位與參考表單由產品負責人提供後才定案。開發不得擅自用敵對品牌或杜撰奇怪名稱填滿正式 Demo。

## 3. 使用者、角色與工作空間

### 3.1 一個帳號，多個角色

`Account` 是登入身分；`RoleMembership` 表示帳號在某個工作空間中的權限。單一帳號可同時是一般會員、合作廠商人員、社區管理者及平台營運者。

使用者必須明確切換 `Workspace`，不可因為登入過某角色而混用資料。Demo 快速登入提供固定、彼此隔離的人物。

### 3.2 個人授權、受益人與服務地點

會員是對話、付款與 `ExecutionGrant` 的唯一授權主體。受益人可以是父母等未持有 AIWave 帳號的人，但不因此取得權限或被推定已同意分享資料。任務可選擇「我家」「爸媽家」等多個服務地點；競賽版不建立家庭共同帳號、共享點數或代理授權。

### 3.3 三種資料範圍

- `personal`：個人訂單、點數、偏好、提醒與行程。
- `group`：使用者自行建立及命名的群組；不要求家庭／朋友／情侶等類型。
- `community`：真實社區組織，含住戶、管理者、公告、設施與社區服務，不是 Group 的一種。

社區不是註冊必填。會員可加入多個社區並設定預設社區；社區管理權另行申請與人工審核，競賽版不假裝完成真實身分驗證。

## 4. 手動流程與自然對話 Agent

### 4.1 手動永遠可用

所有交易功能先有完整手動路徑。Agent 負責理解、規劃、預填、比較、導覽與受控執行，不建立另一套隱藏流程。Agent 與手動 UI 共用 `TaskDraft`；使用者修改值優先，切換操作方式不得遺失對話、草稿、選項或驗證錯誤。

### 4.2 自然對話層與確定性行動層

Agent 不再把 LLM 限縮成單句 JSON 抽取器，也不把每句自由文字強迫轉成交易。每輪先辨識一般對話、產品求助、生活詢問、探索方案、規劃任務、執行操作或暫停／取消，再決定是否呼叫能力。

一個需要資料或操作的回合分兩階段：

1. LLM 根據目前 Session 歷史、任務狀態、可用 capability 與知識內容，產生自然回覆、釐清需求及提出結構化工具計畫。
2. 平台執行並驗證工具；把確定性 facts 回傳給 LLM 組織 grounded 回覆，並以權威卡片呈現 Provider、價格、時段、點數、狀態及操作按鈕。

LLM 可自由承接語氣、代名詞、省略句、修正與反悔，但下列內容只由確定性模組裁決：

- 現在時間與相對日期。
- capability、服務、據點、方案、庫存與時段是否存在。
- 金額、點數、退款與活動上限。
- Account、RoleMembership、Workspace 與 API scope。
- 訂單狀態轉移、冪等、稽核與資料隔離。

安全模板只用於模型失敗、授權摘要、交易結果與必要法遵；正常對話不以固定句型或同義詞表取代語意理解。

### 4.3 Conversation Session

對話 Session 是獨立聊天上下文。產品必須提供新對話、歷史列表、重新開啟、重新命名及封存。新 Session 不帶入舊聊天內容，但不刪除舊 Session 已建立的 `TaskDraft`、Booking、Order、點數或行事曆事項。

跨 Session 只使用會員明確保存的偏好／地址及正式系統紀錄，不自動把其他聊天全文塞進 prompt。會員可明確「繼續此對話」或「引用此任務」。獨立 AI 頁與側欄延續目前選中的 Session，而不是永遠強制載入 latest。

### 4.4 授權與執行

低風險讀取、說明、比較與草稿可直接做。會產生交易或外部影響時，會員核准有範圍與期限的 `ExecutionGrant`，至少包含 Provider、時間範圍、預算／點數上限與到期時間。超出授權或條件改變時必須停下再確認。

生活任務包逐項可編輯、暫緩、刪除或更換 Provider，最後只對選中項目一次授權。跨 Provider 不假裝具原子交易：逐項執行，部分失敗保留成功項並重新規劃失敗項。

## 5. 服務選擇、生活圈、預約與訂單

平台不把廠商當成黑箱媒合結果。正常預約流程是選服務／方案、從核准清單選據點或服務範圍、依需求選資源、從真實空檔選時段，最後檢查價格、點數、個資及取消規則。

服務探索分兩種：

- **我去找服務**：以目前位置、保存地址、社區或會場為起點，依步行／機車與 N 分鐘門檻建立時間可達生活圈，適用餐飲、門市、藥局、取貨點等。
- **服務到我家**：依 Provider 明確承諾的行政區或其他服務範圍判斷，適用清潔、修繕、外送與宅配；不可因據點較近就推定可到府。

Agent 可排序並說明 1–3 個建議，但會員保有最終選擇權。所有頁面的進度、數量與待辦讀取同一份 `StatusEvent` 事件流。

## 6. 共用平台核心

各服務不是一張塞滿 nullable 欄位的萬用訂單。每個 domain flow 有自己的深層介面，底層共用：

- 身分、角色、scope 與稽核。
- `TaskDraft`、確認與 `ExecutionGrant`。
- Booking／Order 與 `StatusEvent`。
- 點數、Demo 支付、退款與沖銷。
- 通知中心與行事曆 projection。
- `ProviderConnector`、錯誤復原與冪等。

### 6.1 點數、回饋與成就

競賽版使用可重置、明確標示 Demo 的 OPENPOINT 情境帳本。基礎交易展示點數折抵；指定活動在符合資格的完成事件後才發放 Demo 回饋，重放不重複，取消／退款依規則沖銷。

生活成果是單次任務包的完成摘要；Steam 式成就解鎖只是一個事件驅動、僅解鎖一次的愉悅提示，不做 XP、等級、每日登入、排行榜或角色養成，也不直接發點。

### 6.2 通知、主動關懷與行事曆

通知中心保存已讀狀態、scope、深層連結與安靜時段；外部推播之後再接。主動關懷採「生活情境事件 → 關懷候選 → 政策允許後的關懷訊息」，與交易通知分開計數。

AIWave 行事曆是 Booking、LifeTask、提醒、Group 與 Community 事件的統一 projection，不取代完整 Google／iCloud Calendar。

### 6.3 LLM Wiki

競賽版使用少量、另行整理且經審核的 Wiki 文件，分成生活指南與產品說明兩個知識域；依知識域將全部已發布內容放入 LLM context，不先建 RAG、Embedding 或向量資料庫。

生活指南可產生通用準備項目並在會員同意後連到 Catalog；產品說明只回答已發布功能並提供白名單導覽，不插入促銷。兩者都必須附來源、版本與更新日期；無資料時回答不知道。

## 7. 合作廠商接入

三種接入方式實作同一個 `ProviderConnector`：

1. 標準接入：Provider 直接實作 AIWave Partner API。
2. Adapter 接入：AIWave 將既有 API 映射到內部契約。
3. 工作台接入：沒有 API 的 Provider 使用合作方後台。

Provider 是據點、方案、資源、時段、接單與履約狀態的權威來源；AIWave 是會員確認、跨場景任務、點數、通知與稽核的權威來源。fake upstream 必須獨立執行、實作同一契約並支援 seed、reset、延遲、錯誤與狀態未知。

## 8. AIWave MCP

MCP 是讓遠端 AI 在授權範圍內操作 AIWave 的入口，不是站內聊天室專用，也不是廠商 API 的別名。正式入口是遠端 Streamable HTTP Gateway；server 無狀態，只能透過 Platform API 操作，不直連 DB。MCP tool 與 Web／Agent 共用 capability、權限、schema、確認、冪等與稽核規則。

MCP 不進五分鐘主 Demo，改以架構與備用證據呈現。

## 9. Web 體驗與設計審批

會員主導覽固定為首頁、點數兌換、AI、服務、會員中心。首頁整合點數、消費、近期行程／待辦、推薦、關懷卡與常用功能；行事曆由首頁卡片進入。

AI 主頁包含新對話按鈕、Session 歷史及目前對話；側欄共享目前選中的 Session。聊天以自然文字為主，只有查到權威資料或可執行操作時才顯示方案、指南、授權與結果卡片。

正式改寫 Vue 前仍應先交付並核准 HTML 方向。介面符合 WCAG 2.2 AA，驗證 390px 與 1440px。

## 10. DemoWorkspace 與重置

每位測試者使用隔離的 `DemoWorkspace`，包含帳號、訂單、點數、Agent Session／草稿、行事曆、通知、Group、Community、活動與成就資料。重置時平台、fake upstream、seed version 與遠端 ID 一起回到相容版本。

## 11. 完成定義

任何可見功能必須滿足：

- 有實際 handler 和後端資料，不是靜態 HTML 或無作用按鈕。
- 重新整理、上一頁與重新登入後狀態一致。
- 帳號、角色、Workspace、Provider 與 scope 隔離正確。
- 有成功與至少一條可恢復失敗路徑。
- 支援 reset，數字跨頁使用同一來源。
- 390px／1440px 與 WCAG 2.2 AA 基本驗證通過。
- 對該發佈範圍已納入的 domain、API、Web、Agent 或 MCP 入口，測試須覆蓋主要閉環；已明確延後的入口不是五分鐘 Demo 的完成門檻。

Agent 另須通過同義改寫、上下文承接、修正／反悔、非交易對話與新 Session 隔離矩陣；自動測試驗證行為與 facts，不逐字比對自然文案。

未符合以上條件的功能不得放在 Demo 主路徑，也不得用靜態假數字宣稱已完成。

## 12. 實作順序

1. 同步規格、領域詞彙、Kiro spec 與 Demo runbook。
2. 改造自然對話 Agent、兩階段工具回合與 Session 管理。
3. 建立 LLM Wiki 文件格式、內容治理與小語料載入。
4. 建立會場／社區時間可達生活圈與到府服務範圍。
5. 串接主動關懷、情境式生活指南與協助式商務。
6. 完成可編輯任務包、點數活動、生活成果、成就提示及 Provider 結算投影。
7. 依五分鐘 runbook 整合並驗收 Demo。
8. Web 穩定後再處理 MCP、LINE／Discord、醫療、語音與正式 AWS。

## 14. 明確延後與待驗證

- LINE／Discord、醫療、語音與正式 AWS 部署延後。
- 正式 OPENPOINT 發點、品牌贊助、Provider 合約、成功服務費率與會計／稅務規則待官方或訪談驗證。
- Amazon Location `CalculateIsolines` 是正式／加分方案；必要 Demo 先使用固定且標示清楚的 GeoJSON，AWS 權限與覆蓋品質另行驗證。
- 中元、颱風、搬家等生活指南必須另找官方或授權來源並人工審核；不得直接複製第三方文章。
- 目前定位只在會員主動點擊後單次使用，預設不保存、不背景追蹤。
