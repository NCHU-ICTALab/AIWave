## 1. 定位與北極星指標

**[已確認需求]** AIWave 是會關心會員生活、並在取得同意後把事情做到底的 AI 生活管家。

```text
基礎生活服務與可追蹤履約
→ 自然對話理解生活目標
→ 可編輯的跨服務任務包
→ 一次有界授權
→ Provider 逐項履約
→ 主動情境與可信生活指南
→ 生活成果、回饋與完成後商業事件
```

**[已確認需求]** 北極星指標是「生活任務完成率」。指南開啟、推播點擊、消費轉換與成功服務費是輔助指標，不得以製造焦慮或無效互動換取成長。

**[合理推導]** 主痛點是會員缺少從生活情境到跨服務履約完成的編排層；次痛點是異質 Provider 接入及在地需求與供給的連結。這不是命題方已正式確認的企業痛點，仍需訪談。

## 3. 使用者、受益人與服務地點

**[已確認需求]** 會員是登入、對話、付款與 `ExecutionGrant` 的唯一授權主體。受益人可選填，例如父母；競賽版不替受益人建立帳號，也不推定其同意資料分享。

**[已確認需求]** 同一會員可有多個服務地點，例如「我家」「爸媽家」。生活任務必須明確指定履約地點；服務地點與 Provider 的門市／據點 `Location` 不同。

競賽版不做家庭共同帳號、共享點數或代理授權。正式版若加入，須另建權限與同意模型。

## 4. 主動關懷模型

### 4.1 三階段

1. **生活情境事件（LifeContextEvent）**：公共日曆、會員明確授權資料或標示清楚的 Demo 事件。
2. **關懷候選（CareCandidate）**：系統判斷可能值得提醒，但尚未送達。
3. **關懷訊息（CareMessage）**：通過類別、頻率、安靜時段與送達方式後，實際呈現給會員。

**[已確認需求]** 競賽版預設只顯示站內卡片；完整偏好設定不進主 Demo。正式版提供安靜／平衡／關心模式作預設，再允許節日、行事曆、天氣、生活服務與地方文化逐類覆寫。一般關懷與訂單、付款、預約異動等交易通知分開計數。

### 4.2 允許資料來源

競賽版白名單：

- 公共節日與節氣資料。
- 會員主動授權的行事曆、保存地址、提醒偏好。
- 明確標示為 Demo 的固定天氣或情境事件。

不使用背景定位、聯絡人、相簿、郵件、秘密行為推論，或由購買紀錄推測健康／家庭／經濟狀況。

### 4.3 關懷卡最低內容

- 為何現在提醒。
- 使用了哪些授權資料。
- 內容來源與更新日期。
- 忽略、稍後、關閉此類提醒及「幫我準備」。

主 Demo 不操作提醒設定，但卡片本身保留透明與關閉入口。

## 5. 時間可達生活圈

### 5.1 兩種服務探索

**我去找服務**使用時間可達生活圈：以目前位置、服務地點、社區入口或會場為起點，依步行／機車與 N 分鐘門檻顯示可達範圍及範圍內餐飲、購物、藥局、取貨等據點。

**服務到我家**使用 Provider Service Area：依 Provider 承諾的縣市、行政區或覆蓋規則判斷清潔、修繕、外送與宅配是否可履約。據點接近不代表可到府。

### 5.2 Demo 固定情境

**[Demo／示意資料]** 起點為使用者指定的「華南銀行國際會議中心（臺北市信義區松仁路 123 號）」。主展示為步行 10 分鐘，可切步行 15 分鐘及機車 10 分鐘。

必要版本使用預先建立、可重置且明確標示 Demo 的 GeoJSON 與 Provider 座標。畫面不顯示即時路況、導航或未經驗證的最近距離。

### 5.3 正式／加分方案

**[待官方或訪談驗證]** AWS 權限與台灣覆蓋確認後，可透過抽象 `ReachabilityProvider` 接入 Amazon Location Service `CalculateIsolines`；逾時或不可用時回到固定 Demo 範圍。該 API 可依起點、交通模式與時間／距離門檻計算 isoline，官方文件見 [Calculate Isolines](https://docs.aws.amazon.com/location/latest/APIReference/API_CalculateIsolines.html)。

目前定位只在會員點擊「使用目前位置」後單次取得，預設不保存、不背景追蹤；Demo 不觸發瀏覽器定位權限。

> AWS 能力描述依官方文件重新表述；實際權限、價格、覆蓋與限制須部署前再驗證。

## 6. 情境式生活指南與協助式商務

### 6.1 產品角色

AIWave 不重做另一個生活知識網站，而是把可信指南轉成可勾選清單、在地服務、採買 `TaskDraft` 與可追蹤履約。

生活指南文章至少包含：主題、觸發條件、日期／地域、步驟、必要／可選準備項目、來源、授權狀態、更新日期、審核狀態及是否允許推播／商業使用。

第三方產品 [初級大人手冊](https://adultingguide.tw/) 只作「第一次遇到生活麻煩時提供整理內容」的產品形態參考；沒有授權時不得擷取、複製或改寫其文章作商業知識庫。

### 6.2 Demo 內容

- **[Demo／示意資料]** 主案例：中元普渡準備。
- **[待實作功能]** 延伸文章：颱風前準備、搬家／入厝。
- **[已確認需求]** 中元短場景只走「提醒 → 有來源指南 → 準備清單 → 幫我準備 → 生活圈商品類別與 OPENPOINT Demo 試算」，不現場重跑完整下單，也不靠旁白補充後續結果。

內容須說明各地與家庭習慣可能不同，不把可選物品說成絕對必買，不以宗教焦慮促成消費。

### 6.3 準備項目與 Catalog

LLM 只依指南與會員回答整理通用 `PreparationItem`，包含用途、必要／可選、數量依據與限制；不得產生 SKU、價格、庫存、門市或點數條件。Catalog／Provider 才能決定具體商品與可取得地點。

協助式商務採兩階段：推播先提供生活價值；會員開啟指南並點「幫我準備」後，才顯示必要、可選、便利建議及明確標示的合作推薦。

## 7. 自然對話與 Session

詳細契約見 [17](17-conversational-agent-session-and-llm-wiki.md)。本規格要求：

- LLM 看到目前 Session 的對話與任務狀態，不只看單句。
- 每輪先理解對話目的；一般聊天、FAQ、指南、探索、規劃、執行與取消分流。
- LLM 先提出工具計畫，平台執行後再由 LLM 根據 facts 自然回答。
- 方案、價格、時段、點數、狀態與授權使用結構化權威卡片；自然文字負責解釋。
- 新對話不承接舊聊天全文；會員可重開、重命名或封存舊 Session。

## 8. 生活任務包與授權

任務包保存來源情境、受益人、服務地點及既有 `TaskDraft.id` 清單；子任務仍走正式 `TaskDraft → submit → Booking／Order` 閉環。

會員可逐項修改、暫緩、刪除及更換 Provider。系統重新計算總額、時段衝突與授權範圍後，只針對選中項目提出一張 `ExecutionGrant`。

跨 Provider 逐項執行：成功項保留；失敗項顯示原因與替代方案。替代方案超出 Provider、時段、預算或點數範圍時重新確認。重試不得重複下單或扣點。

## 9. 生活成果、成就、點數與結算

### 9.1 三種完成結果

- **生活成果**：單次任務包的完成摘要。
- **成就解鎖提示**：由完成事件觸發、僅解鎖一次的 Steam 式微互動，沒有經濟價值。
- **OPENPOINT Demo 回饋**：由可配置活動規則在符合資格的完成事件後發放。

三者不得混為一談。成就不發點；完成前不發回饋；事件重放不重複；取消／退款按規則沖銷。

### 9.2 Demo 活動預算

**[Demo／示意資料]** 回饋來自獨立 Demo 活動預算池，記錄期間、資格、會員上限、總預算、示意贊助來源、已承諾／已發放／已沖銷。未來可由品牌、Provider 或平台出資，但目前不指定正式合作方。

### 9.3 Provider 成功服務費

會員端只看服務價格、點數折抵、應付金額與活動回饋。Provider／平台結算端在 Booking／Order 完成後產生一次 Demo 成功服務費，顯示成交金額、示意費用、Provider 贊助回饋（如有）及預估淨額。建立、接單、取消、失敗與未履約不收費；退款建立沖銷事件。

主報告只講：消費者免費、Provider 履約完成後支付成功服務費、活動回饋未來可由合作方贊助。

## 11. 驗收矩陣

| 能力 | 必要證據 |
| --- | --- |
| 自然 Agent | 同義改寫得到等價意圖；代名詞／省略句承接；修正、反悔與暫停不誤執行 |
| 非交易對話 | FAQ、指南、比較與一般詢問不強迫建立任務 |
| Session | 新建、列表、重開、重命名、封存；新 Session 不引用舊方案；舊正式任務仍存在 |
| LLM Wiki | 兩知識域隔離；只載入已發布小語料；回答附來源；無證據時說不知道 |
| 權威 facts | LLM 不改價格、日期、時段、點數、Provider、庫存、狀態及授權；卡片讀結構化資料 |
| 生活圈 | 步行／機車、10／15 分鐘切換；GeoJSON 與清單一致；到府服務不以可達圈誤判 |
| 主動關懷 | 候選與實際送達分開；卡片顯示原因、資料與來源；忽略／稍後／關閉可用 |
| 指南商務 | 必要／可選／合作推薦分開；PreparationItem 不冒充 SKU；未同意不建草稿 |
| 任務包 | 逐項修改／刪除；user 值優先；一次有界授權；部分失敗與重試冪等 |
| 點數與結算 | 折抵可重算；完成前零回饋／零費用；重放不重複；取消／退款沖銷 |
| Demo | 五分鐘內完成；不靠旁白補足缺少結果；390px／1440px 與鍵盤可操作 |

自然度由固定情境人工評分；自動測試不逐字比對 LLM 文案，只驗證意圖、工具、state、facts 與副作用。

## 12. 明確不做

- 本輪不做完整角色養成、XP、升級、每日登入、排行榜或服裝。
- 不做家庭共同帳號、共享點數或代理授權。
- 不做背景定位、移動軌跡分析、即時導航或未驗證的最近服務。
- 不做大型 RAG、Embedding 或向量資料庫；文件量增長後再升級。
- 不宣稱正式 OPENPOINT 發點、品牌贊助、Provider 費率或合作條件。
- 不複製未授權第三方內容，不以 LLM 無來源生成民俗知識。
- 不讓推播直接製造焦慮、建立購物車或強迫消費。

## 13. 文件與內容待辦

- 依實際發布功能編寫點數、預約／取消、TaskDraft、通知／行事曆及生活圈 FAQ。
