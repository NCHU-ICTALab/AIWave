## 1. Demo 要證明什麼

五分鐘內只證明一件核心價值：**AIWave 能把一個自然語言生活目標轉成跨服務方案，經會員確認後真正驅動廠商並追蹤完成。**

評審必須直接看見：

1. AI 能理解多意圖、上下文及限制，不是關鍵字目錄。
2. 點數、價格、廠商、時段與群組條件共同影響方案。
3. 寫入操作有預覽、權限與確認，數字由規則產生。
4. 廠商是獨立 HTTP fake server，不是前端 fixture。
5. 同一能力能被 Web、AI 與 MCP 共用，且上游故障可恢復。

## 2. 固定 Hero 腳本

登入會員「小圓」，輸入：

> 「爸媽週六要來，浴室燈壞了、冷氣也很久沒洗，幫我安排一下，OPENPOINT 能省就省。」

### 五階段流程

| 階段 | 畫面與互動 | 系統證據 |
| --- | --- | --- |
| 1 理解目標 | 使用者訊息在右；AI 串流回覆並顯示「正在整理需求」 | 上下文、多意圖與 structured plan |
| 2 補齊條件 | 聊天框上方出現日期、地址及群組範圍按鈕；只問缺少資料 | 動態題組、可操作選項、active scope |
| 3 比較方案 | 顯示水電與清潔方案、時間、價格、評分、點數及取捨 | Vendor API、媒合規則、點數引擎、可解釋推薦 |
| 4 一次確認 | 顯示將建立的任務、使用資料、折抵、總額及可取消項目 | 權限層級、預覽、確定性計算、稽核 |
| 5 執行追蹤 | 確認後建單；切到廠商後台更新狀態，再回 AI／訂單查看 | fake server、adapter、事件、跨角色狀態回流 |

### 群組加碼

AI 可以詢問是否把同類需求分享至家庭／社區群組。只有在會員同意後才聚合需求；展示共同時段或群組價格，但不揭露其他成員個人資料。時間不足時可跳過，不影響主閉環。

## 3. 五分鐘節奏

| 時間 | 內容 |
| --- | --- |
| 0:00–0:30 | 一句痛點與登入後首頁：生活服務分散，會員必須自己切 App、重填及追進度 |
| 0:30–2:10 | AI 輸入 Hero 句子、串流理解、補條件、產生跨服務方案 |
| 2:10–3:05 | 展開點數／優惠計算與廠商比較，完成一次確認 |
| 3:05–3:45 | 廠商後台收到需求、報價或更新履約狀態 |
| 3:45–4:20 | 回到會員 AI／訂單，看到同一筆任務的狀態回流 |
| 4:20–4:45 | 注入一次慢速或 503，展示進度、降級、替代與重試 |
| 4:45–5:00 | 顯示 OpenAPI／MCP 同契約及商業飛輪，回到一句話定位 |

## 4. 畫面範圍

### 會員首頁

- 點數及本月消費。
- 今日待處理事項與訂單摘要。
- 輕量 AI 入口。
- 個人推薦、常用功能與活動。
- 所有卡片均有後續操作；推薦可逐張不感興趣並復原。

### 全頁 AI

- 對話區佔主要空間，使用者與 AI 分左右。
- 輸入區固定在可視區底部，訊息內容於內部捲動；在訊息區任意位置均可使用滾輪。
- textarea 禁止手動 resize，依內容自動增高至上限，超過後內部捲動。
- 可操作選項放在輸入區上方，支援鍵盤、焦點與螢幕閱讀器。
- 串流顯示可理解的進度、工具名稱、等待原因及完成狀態，不顯示模型原始隱藏推理。

### 廠商後台

- 新需求佇列、結構化摘要、聯絡資訊授權狀態。
- 報價、狀態、回覆及履約事件。
- 狀態更新必須回到平台，不能只改前端畫面。

### 訂單與點數

- 訂單依狀態分組並可折疊；展開才顯示完整時間軸。
- 點數試算顯示使用前後金額與規則來源。
- AI 產生的方案可深層連結到指定訂單或試算。

## 5. Fake server 與失敗橋段

- fake vendor server 是獨立 process，實作正式 OpenAPI 契約。
- 前端只呼叫平台 `/api/v1`；`VENDOR_MODE` 由平台後端讀取。
- Demo 可注入慢速成功、503、格式錯誤或一次性逾時。
- 平台必須顯示「服務暫時較慢／已使用備援／可重試」，不能把 500 或空白丟給會員。
- reset 後資料、故障及計數回到 `demo_seed_v1`。

## 6. 量化方式

Demo 彩排前記錄不用 AIWave 時完成同一任務的基準，再量測：

- App／頁面切換數。
- 手動欄位及重複欄位數。
- 從描述需求到取得方案及完成確認的時間。
- 點數與優惠節省金額。
- 一個 vendor contract 被 Web、AI、MCP 重用的能力數。

未量測前不在簡報寫入宣傳數字。

## 7. P0 驗收

- [ ] Hero 句子穩定拆成修繕、清潔、時程與點數任務。
- [ ] 低信心或缺少資料時會澄清，不出現無關寄件或美食服務。
- [ ] 每個建議都可操作，且有理由、價格、時段與限制。
- [ ] 確認前不建立訂單；確認後廠商後台能看見同一案件。
- [ ] 訂單狀態回流到 AI、首頁摘要及折疊訂單頁。
- [ ] fake server 慢速、錯誤及 reset 可穩定重演。
- [ ] 1440×900 與 390×844 均走完流程，符合 WCAG 2.2 AA。
- [ ] 鍵盤能完成聊天選項、確認、訂單展開與重試。
- [ ] 沒有展示用角色切換、重設或 fixture 控制項出現在會員介面。
