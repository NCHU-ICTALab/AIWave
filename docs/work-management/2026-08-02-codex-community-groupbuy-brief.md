## 0. 前置說明（請先讀完再動手）

**這是對「既有專案」的增修，不是新專案。**

動工前請先做以下事情，不要跳過：

1. 掃過現有 repo，確認：使用的框架與版本、狀態管理方式、路由設定、樣式方案（Tailwind / CSS Modules / styled-components）、既有的元件庫與設計 token（顏色、圓角、間距、字體）、既有的資料夾結構與命名慣例。
2. **新頁面一律沿用既有視覺風格與元件**。不要引入新的 UI 框架、不要換配色、不要自創設計語言。若既有專案已有 Button / Card / Modal / Table 等共用元件，直接用，缺什麼才新增，且新增的元件要放進既有的共用元件目錄並符合原有 API 風格。
3. 若既有專案已有 mock 資料層，**沿用它的模式擴充**，不要另立一套。
4. 動手前先簡述你的實作計畫（要新增哪些路由、檔案、元件），確認方向再開始寫。

**範圍限制**：本次只做 **Web 應用程式**。LINE Bot / Discord Bot 由另一位成員實作，**不要**寫 Bot 端程式、不要串接 Messaging API、不要做聊天室模擬頁面。你要做的是把 Bot 需要的資料與行為，**封裝成清楚的服務層介面**（見 §6）。

**資料**：全部是 mock 假資料，純前端，不接後端。但**假資料要像真的**（見 §3）。

## 1. 背景（Context）

我們在參加統一企業（7-ELEVEN 母集團）命題的創業競賽，隔天下午簡報。評審是該企業的專案經理，最在意 **怎麼賺錢** 與 **能不能落地**。企業方明講：內部唯一能自主決定的優惠只有 OpenPoint，其他優惠都要跨部門談——所以我們的方案必須**不依賴企業額外掏錢補貼**。

提案：**以「社區管委會」為單位的訂閱制 AI 智慧社區平台，主打社區團購 + 社區知識問答**。

現況對比：7-ELEVEN 現在的團購是 LINE 群裡小編發文、住戶留言「+1」、人工核單，大家再跑同一間門市取貨。我們把它反過來——**商品直送社區、AI 取代人工核單**。

競品：智生活科技（SmaDay）是台灣智慧社區既有玩家，但走硬體路線（智慧包裹櫃、雲端對講、充電樁），重資產、老舊社區難導入。**我們是純軟體 + Bot，零硬體、可免費試用**。

## 2. 商業模式（簡報核心，介面上必須看得見）

```
管委會 ──每月訂閱費──▶ 平台
                        │
平台 ──提供──▶ 社區管理系統（公告/包裹/報修/預約/會議/Wiki）
                        │
平台 ──提供──▶ 團購折扣價給全體住戶
                        │
住戶下單 ──▶ 廠商出貨到社區管理室 ──▶ 平台向廠商抽成
```

四個關鍵設計，必須在介面上被看到：

1. **管委會付訂閱費**，依戶數分級：1–30 戶 $999/月、31–50 戶 $1,499/月、51–100 戶 $2,499/月、101–200 戶 $3,999/月、201–500 戶 $6,999/月、500 戶以上客製報價。級距表是資料（`web/app/src/data/communityDemoSeed.ts` 的 `SUBSCRIPTION_TIERS`），任何頁面都由 `planForHouseholds(householdCount)` 對照，不再寫死金額。
2. **住戶折扣的來源是訂閱費，不是廠商吐血也不是集團補貼**。商品要同時顯示「市價 $149 → 社區價 $135」，旁邊放問號 tooltip：「本社區已訂閱 AI 智慧社區服務，價差由社區訂閱費回饋，非廠商補貼」。**這句話是我們繞開「企業給不出優惠」限制的關鍵，一定要出現在畫面上。**
3. **平台向外部廠商抽成**：非集團廠商開團抽成交額 3%；集團自家商品免抽，讓自家價格更有優勢。
4. **零硬體、免施工、可免費試用 3–6 個月**。

## 4. 社區 LLM Wiki（新功能，請完整實作）

這是社區的知識庫，Bot 與 Web 共用同一份資料源。住戶問「垃圾車幾點來」「可以養狗嗎」「裝修要申請嗎」，系統從 Wiki 找答案。

### 4.1 資料結構

每則 Wiki 條目至少包含：

```ts
{
  id: string
  category: string          // 見下方分類
  title: string             // 「垃圾清運與資源回收」
  question_variants: string[] // 住戶可能的問法，用於檢索比對
  content: string           // Markdown，正式答案
  short_answer: string      // 一句話版本，給 Bot 回覆用
  source: string            // 「社區規約第 12 條」「管委會 2025.03 決議」
  updated_at: string
  updated_by: string        // 「總幹事 李文彬」
  visibility: 'resident' | 'committee'  // 部分條目只有管委會看得到
}
```

### 4.2 分類與必備條目（至少 40 則，以下為必須有的）

**生活作息**
- 垃圾清運時間與地點（週一至週六 19:30–20:00，B1 垃圾集中區；週日不收）
- 資源回收分類規則與時段
- 大型家具／家電廢棄物處理流程與費用

**門禁與訪客**
- 訪客如何進入、訪客停車格使用規則（限 3 小時，需登記）
- 磁扣遺失補辦流程與費用（$200／個，需本人攜證件）
- 外送員／快遞可否進入

**包裹**
- 代收包裹規定、保管期限（7 天）、超商包裹可否代收
- 大型包裹、冷凍宅配的處理方式（冷凍不代收）
- 取件時間與取件碼使用方式

**裝修與工程**
- 裝修申請流程、需備文件、保證金（$20,000，完工退還）
- **施工時間限制**（週一至週五 09:00–12:00、14:00–17:00；週六 09:00–12:00；週日及國定假日禁止）
- 敲打作業額外規定、電梯保護措施

**寵物**
- 是否可飼養（可，需登記；限中小型犬）
- 公共區域牽繩、進電梯規定、排泄物處理
- 禁止進入的區域（健身房、閱覽室）

**車位與充電**
- 車位租賃、機械車位操作與注意事項
- 電動車充電樁使用方式、計費（每度 $6，App 扣款）
- 訪客停車、臨停規則

**公設**
- 各公設開放時間、預約方式、使用規則、清潔押金
- 健身房未成年使用規定
- 烤肉區申請與噪音時限

**費用與行政**
- 管理費計算方式、繳納方式與期限、逾期滯納金
- 遷入／遷出流程、租客登記義務
- 區分所有權人會議、投票與委託書

**維修與緊急**
- 家戶內漏水責任歸屬（共用管線 vs 專有部分）
- 停水停電應變、緊急聯絡電話
- 火警、地震避難動線與集合點
- 電梯受困處理程序

**社區服務**
- 團購怎麼參加、取貨在哪、退換貨規則
- 生活服務（冷氣清洗等）如何預約、社區價說明

### 4.3 Wiki 的三個介面

**A. 住戶端：問答介面**
- 一個對話式輸入框：「有什麼社區問題想問？」
- 送出後顯示：一句話回答（short_answer）＋ 展開完整內容 ＋ **標註來源**（「依社區規約第 12 條，2025.03 更新」）＋「相關問題」推薦 3 則
- 檢索用簡單的關鍵字比對（比對 title + question_variants + content），**不要真的呼叫 LLM API**，但介面要做出「AI 正在思考」的打字動畫，讓 demo 看起來是 AI
- 找不到答案時：「這題我還不會，已轉知管委會」＋ 一鍵送出提問給管委會
- 首頁放 6 顆熱門問題快捷鍵（垃圾車時間／訪客停車／裝修申請／寵物規定／管理費／包裹代收）

**B. 住戶端：Wiki 瀏覽頁**
- 依分類瀏覽、搜尋、標記常用

**C. 管委會後台：Wiki 管理**
- 條目的新增／編輯／停用，Markdown 編輯器
- **未回答問題清單**：住戶問了但沒答案的問題，管委會可直接補寫成新條目（這個回饋迴圈是簡報亮點——社區的知識會越用越完整）
- 每則條目的**被查詢次數**排行，讓管委會知道住戶最在意什麼
- 條目的 visibility 切換

### 5.3 團購功能（完整實作）

**開團（後台）**
- 商品名稱、圖片、描述
- **市價**與**社區團購價**，自動算折扣（顯示「社區訂閱優惠 -$14」）
- **規格／品項變體**：如「單入 $135／六入 $780」「巧克力味／抹茶味」，各規格可不同價格與庫存。**這點很重要**——一則團購常含多個品項，正是人工核單最容易出錯的地方，也是 AI 核單的價值所在
- 成團門檻（如滿 10 件）、截止時間、每人限購
- 預計到貨日、取貨地點（管理室／A 棟大廳）
- 供應商（集團／外部，外部自動顯示抽成率）

**跟團（住戶端）**
- 列表：進行中／即將截止／已成團／歷史
- 詳情頁必備：
  - **進度條**「已跟團 7 / 10 件」，成團後轉「已成團 🎉」
  - **倒數計時**「剩餘 2 天 14 小時」
  - 規格選擇 + 數量加減器
  - 「我要 +1」主行動按鈕（沿用大家熟悉的用語）
  - **已跟團名單**：「A 棟 12F 王先生 +2」「B 棟 5F 陳太太 +1」（樓層可見、姓名部分遮蔽）——社區團購的信任感來源，一定要有
  - 留言／提問區
- +1 後可改數量、可取消（截止前）

**結單與後續（後台）**
- **整單彙總**：依住戶匯總（誰買了什麼幾件多少錢）＋ 依規格匯總（單入 30 件、六入 8 件，方便叫貨）
- 一鍵匯出 CSV（前端產生下載）
- 對帳狀態：已付款／未付款
- 到貨後「通知取貨」→ 住戶端出現取貨碼
- 取貨核銷：輸入取貨碼標記已領
- **分潤試算**：成交額 $X、平台抽成 $Y、社區回饋 $Z

**團購 mock 案例（至少 5 筆）**
1. 進行中、快成團的零食（單入／六入兩規格）
2. 已成團、等待到貨的生鮮
3. 可取貨狀態的日用品
4. 已結束、未達門檻（展示失敗情境）
5. 外部廠商開團（後台看得到 3% 抽成）

## 6. Bot 介接的服務層（重要，這是給隊友接的）

Bot 由另一位成員實作。你的責任是把 Bot 會用到的資料與行為，**收斂成一個乾淨、有型別、可替換的服務層**，未來換成真 API 只要改這一層。

請建立 `src/services/` （或沿用既有專案的等價目錄），包含：

```ts
// wiki.service.ts
askCommunity(query: string, householdId: string): Promise<WikiAnswer>
listWikiEntries(category?: string): Promise<WikiEntry[]>
reportUnanswered(query: string, householdId: string): Promise<void>

// groupbuy.service.ts
listActiveGroupBuys(communityId: string): Promise<GroupBuy[]>
getGroupBuy(id: string): Promise<GroupBuyDetail>
joinGroupBuy(params: { groupBuyId, variantId, quantity, householdId }): Promise<Order>
cancelOrder(orderId: string): Promise<void>
listMyOrders(householdId: string): Promise<Order[]>

// community.service.ts
getAnnouncements(communityId: string): Promise<Announcement[]>
getParcels(householdId: string): Promise<Parcel[]>
getMaintenanceSchedule(communityId: string): Promise<MaintenanceItem[]>
createRepairTicket(params): Promise<RepairTicket>
```

要求：

- 所有型別定義集中在 `src/types/`，**匯出成隊友可直接 import 的形式**
- 目前實作全部讀 `src/mock/`，但函式簽章與回傳格式要當成真 API 在設計（含 `Promise`、模擬 200–600ms 延遲、可能的錯誤回傳）
- **寫一份 `docs/BOT_API.md`**：列出每個函式的用途、參數、回傳 JSON 範例。隊友寫 Bot 時直接照這份規格對接，不用讀你的程式碼
- 不要在 UI 元件裡直接讀 mock 檔案，一律經過服務層

## 7. Demo 走查腳本（請確保這條路徑 100% 順暢無 bug）

簡報只有 6–8 分鐘，只會走這一條：

1. 住戶首頁 → 看到 2 件待領包裹、電梯保養公告、進行中團購
2. 點「問社區」→ 輸入「垃圾車幾點來」→ AI 打字動畫 → 回答「週一至週六 19:30–20:00，B1 垃圾集中區，週日不收」＋ 來源標註
3. 再問「裝修可以假日施工嗎」→ 回答施工時間限制 ＋ 展開完整規約
4. 進生活服務 → 冷氣清洗「市價 $3,800／社區價 $3,500」→ 點問號 → tooltip：「價差由社區訂閱費回饋，非廠商補貼」
5. 切到管委會後台 → 開一團「杜拜巧克力」（單入 $135／六入 $780，成團門檻 10 件）
6. 切回住戶端 → 團購頁出現新團 → 選六入 × 1 → 我要 +1 → 進度條 7/10 → 8/10
7. 切回後台 → 整單彙總表出現這筆、成交額 KPI 跳動
8. 後台 Wiki 管理 → 展示「未回答問題清單」與被查詢次數排行（知識越用越完整）
9. 最後停在「訂閱與帳務」頁 → 「本月訂閱費 $999，住戶累計省下 $4,620，社區淨效益 +$3,621」

**角色切換**：提供一個不干擾畫面的切換方式（右上角下拉或懸浮按鈕），可在「住戶王小明」與「管委會主委」之間即時切換，不需登入流程。切換要快，簡報時沒時間登出登入。
